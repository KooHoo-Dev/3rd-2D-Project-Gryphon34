# 좋은 커밋 메시지 작성 가이드

코드를 짜는 것만큼 **변경 이력을 남기는 것**도 중요합니다.
6개월 뒤의 내가, 그리고 함께 일할 동료가 *"이 코드는 왜 이렇게 됐지?"* 를 빠르게 이해할 수 있도록 커밋 메시지를 잘 남기는 습관을 들여봅시다.

---

## 5가지 규칙

1. **제목은 50자 이내** — 무엇을 했는지 한 줄로 요약합니다.
2. **명사형/단정형**으로 작성 — `"~했음"` 보다는 `"~ 추가"`, `"~ 수정"` 형태로.
3. **한 커밋은 한 가지 변경만** — 기능 추가와 버그 수정을 한 번에 커밋하지 마세요.
4. **제목과 본문 사이에 빈 줄** 하나를 둡니다.
5. **본문에는 "왜" 변경했는지** 적습니다.
   - "무엇을" 바꿨는지는 코드 diff를 보면 알 수 있습니다.
   - "왜" 그렇게 바꿨는지는 커밋 메시지에만 남습니다.

## 좋은 커밋 메시지 예시 5선

### 1. 새 기능 추가

```text
더블 점프 기능 추가

상위 스테이지에서 점프 거리가 부족해 진행이 막힌다는 플레이테스트
피드백이 있었음. 공중에서 1회 추가 점프할 수 있도록 PlayerController에
jumpCount 필드를 추가하고, 점프 이펙트 파티클도 함께 연동함.
```

### 2. 버그 수정

```text
적 AI 추적 중 벽 통과 버그 수정

NavMeshAgent의 ObstacleAvoidanceType이 None으로 설정되어 있어
좁은 통로에서 적이 벽을 뚫고 플레이어를 추적하는 문제가 있었음.
HighQualityObstacleAvoidance로 변경하여 해결.
```

### 3. 리팩토링

```text
인벤토리 시스템을 ScriptableObject 기반으로 전환

기존에는 아이템 정보가 코드에 하드코딩되어 있어 신규 아이템을 추가할 때마다
재컴파일이 필요했음. ScriptableObject로 분리하여 에디터에서 데이터만 추가하면
빌드 없이 아이템 확장이 가능하도록 개선.

- 아이템 데이터를 ScriptableObject로 분리
- ItemDatabase 싱글톤 제거 후 의존성 주입 방식 적용
- UnityEvent를 C# event로 변경해 결합도 감소
```

### 4. 성능 개선

```text
총알 이펙트에 오브젝트 풀링 적용

Instantiate/Destroy를 매 발사마다 호출해서 GC Spike가 발생,
연사 시 프레임이 60까지 떨어지는 문제가 있었음.
오브젝트 풀링으로 메모리 할당을 재사용해 144 프레임 안정적으로 유지.
```

### 5. 빌드/설정 변경

```text
Android 빌드 설정을 IL2CPP, ARM64 전용으로 변경

Google Play의 최소 Target API Level 정책에 맞춰 34로 상향.
ARMv7는 deprecated되어 ARM64 단독 빌드로 전환했으며,
그 결과 APK 사이즈가 약 30% 감소함.
```
