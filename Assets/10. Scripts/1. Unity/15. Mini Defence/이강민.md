## 잘한 점

**① 클릭에서 타일까지 가는 흐름이 정확합니다. (14/14)**

```csharp
Vector2 mousePosition = SimpleInput.GetMousePosition();
Vector3 worldMousePoint = Camera.main.ScreenToWorldPoint(mousePosition);
worldMousePoint.z = transform.position.z;
Vector2Int tilePos = grid.WorldToCell(worldMousePoint);
Tile tile = grid.GetTileOrNull(tilePos);
```

스크린 → 월드 → 셀 → 타일. z 값까지 신경 쓰셨고, `GetTileOrNull` 뒤에 null 검사도 있습니다. **이 부분은 손댈 게 없습니다.**

**② 판정과 실행을 메서드로 나눴습니다.**
`BuildableTile()`(놓을 수 있는 타일 찾기)과 `SpawnOne()`(놓기)을 분리하셨습니다. 한 클래스 안이지만 역할이 보입니다.

**③ 로그로 좌표를 확인하며 진행했습니다.**
월드 좌표와 셀 좌표를 각각 찍어 변환이 맞는지 확인하셨습니다.

## 고칠 점

**① `Resources.Load` 경로 형식이 잘못됐습니다.** ← 가장 중요

```csharp
Resources.Load<Unit>("Assets/Resources/Mini Defence/Prefabs/Circle.prefab")
```

두 가지가 틀렸습니다.

- **`Assets/Resources/`를 빼야 합니다.** 경로는 `Resources` 폴더 **안에서부터** 시작합니다
- **확장자를 빼야 합니다.** `.prefab`을 붙이면 못 찾습니다

```csharp
Resources.Load<Unit>("Mini Defence/Prefabs/Circle")   // 이렇게
```

지금은 **항상 null이 반환되어** 다음 줄 `Instantiate`에서 예외가 납니다. 불러온 직후 null 검사를 넣어두면 이런 문제를 즉시 발견할 수 있습니다.

```csharp
Unit prefab = Resources.Load<Unit>("Mini Defence/Prefabs/Circle");
if (prefab == null) { Debug.LogError("프리팹을 못 찾았습니다"); return; }
```

**② 점유를 타일 종류로 표현하고 있습니다.**

```csharp
tile.Kind = TileKind.Blocked;   // 유닛을 놓은 뒤 종류를 바꿔버림
```

재배치가 막히긴 하지만, **그 타일이 원래 건설 패드였다는 정보가 영구히 사라집니다.** 나중에 유닛을 판매하면 그 자리를 다시 `Buildable`로 되돌려야 하는데, 무엇이었는지 알 수 없게 됩니다.

`Tile`에는 이미 점유를 위한 자리가 따로 있습니다.

```csharp
Unit unit = Instantiate(prefab, grid.CellToWorld(tile.Coord), Quaternion.identity);
tile.Unit = unit;   // 종류는 그대로 두고, 점유만 기록
```

**타일의 "종류"(무엇인가)와 "점유"(누가 있는가)는 다른 정보입니다.** 하나로 합치면 되돌릴 수 없게 됩니다.

**③ 검사 조건이 반대 방향입니다.**

```csharp
if (tile == null || tile.Kind == TileKind.Blocked) return null;
```

`Blocked`만 걸러내니 **경로·스폰·목표 타일에는 유닛이 올라갑니다.** "막힌 곳이 아니면 OK"가 아니라 "**건설 패드일 때만 OK**"로 물어야 합니다.

```csharp
if (tile == null || tile.IsBuildable() == false) return null;
```

`Tile.IsBuildable()`은 `Kind == Buildable && Unit == null`을 한 번에 확인해줍니다.

## 다음 과제

**데이터 테이블(지시서 2번)에 착수하지 못하셨습니다.** 이게 이번 과제 배점의 3분의 1입니다.

`switch`로 세 개를 늘어놓은 부분이 정확히 테이블이 필요한 이유입니다.

```csharp
case 0: Resources.Load<Unit>(".../Circle");   // 유닛이 10종이 되면 case가 10개
case 1: Resources.Load<Unit>(".../Square");
case 2: Resources.Load<Unit>(".../Triangle");
```

표를 쓰면 유닛이 몇 종이든 코드는 그대로입니다.

```csharp
UnitDef def = unitTable.Get(selectedId);
Instantiate(def.Prefab, ...);
```

수업의 `EnemyTable`을 옆에 놓고 같은 꼴로 `UnitTable`을 만들어 보세요. `UnitDTO`(문자열) → `Resources.Load` → `UnitDef`(실물) → `Dictionary` 순서입니다.

---

## 사소한 정리

- `switch`의 세 case가 프리팹 이름만 다르고 완전히 같습니다
- `spawnPosition = tile.Coord`는 **셀 인덱스**지 월드 좌표가 아닙니다. `grid.CellToWorld(tile.Coord)`를 쓰세요
- 유닛 종류를 `Random.Range`로 고르는데, 지시서는 **선택**을 요구합니다
- `Camera.main`과 `Resources.Load`를 클릭할 때마다 호출합니다. `Awake`에서 한 번만 하면 됩니다
